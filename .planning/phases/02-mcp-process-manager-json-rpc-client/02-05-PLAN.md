<interfaces>
Public Phase 2 service contract consumed by Phase 4:
- `getMcpProcessManager()` returns gateway-wide singleton keyed by persisted `server.id`.
- `manager.executeToolCall({ serverId, tool, arguments, timeoutMs })` returns a capped MCP tool result or sanitized envelope.
- `manager.getReadyTools()` returns only fresh cache from `Ready` entries; stale cache remains internal/admin-only.
- `manager.disableServer(serverId)` and `shutdownMcpProcessManager()` close transport/process, timers, queues, listeners, and pending work.
- `manager.getServerStatus(serverId, { includeAdminDetails: false })` returns sanitized public state; detailed operation/debug data is not client surface.
- Manager obtains `handle = await createMcpTransport(server, { policy, resolveHost })`; after and only after it classifies Streamable HTTP initialization failure as compatibility-related, it calls `await handle.createLegacyFallback()` to obtain fresh SSE fallback handle. It must not import or call a module-level `createLegacyFallback`.
- A returned transport handle has no `start()` method. Manager constructs `new McpJsonRpcClient(handle.transport, { onNotification, onTransportLifecycle })`, then executes exactly `await client.start()` once before its discovery `initialize`; manager never calls `handle.start()` or `handle.transport.start()`.
- `McpJsonRpcClient.initialize()` validates `initializeResult.protocolVersion` and calls `transport.setProtocolVersion?.(initializeResult.protocolVersion)` before `client.notifyInitialized()`, `client.listTools()`, or `client.callTool()`. Manager discovery order is fixed: construct fresh client; `await client.start()` once; `await client.initialize(...)`; `await client.notifyInitialized()`; `await client.listTools(...)`; cache/state publish.
- Same fixed sequence applies to initial connection, remote reconnect, stdio recovery, and legacy fallback. Legacy fallback sequence is exact: close failed Streamable HTTP handle; `fallbackHandle = await handle.createLegacyFallback()`; construct fresh client over `fallbackHandle.transport`; `await fallbackClient.start()` once; initialize/protocol validation; initialized notification; paginated discovery. Never reuse failed client or call `start` on a handle/transport directly.
- `onTransportLifecycle({ type: "error"|"close", code, retryable: true })` delegates to `manager.handleTransportLifecycle(serverId, event, connectionGeneration)`; manager owns state transition, sanitized audit, crash budget, and bounded recovery.
- `handleTransportLifecycle` treats duplicate terminal events for same `connectionGeneration` as one failure. Idle terminal events mark only that entry `Degraded`, remove tools from `getReadyTools()`, audit sanitized lifecycle metadata, then schedule bounded recovery unless budget reaches `Error`. In-flight terminal events first let client reject current pending work; manager returns one retryable D-15 envelope, releases counters/queue exactly once, audits failed `tools/call` plus lifecycle metadata, and never requeues/replays call. Intentional disable/shutdown close sets `entry.closing` and must not consume budget or schedule recovery.
- An entry is idle only when queue empty, `inFlight === 0`, no cancellation grace, and no initialize/discovery/reconnect/retry operation is active. Manager stops stdio only when releasing process-cap slot, disabling, or shutting down; remote entries remain reused while enabled.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted server config → process/remote lifecycle | Approved database configuration becomes shared gateway resource. |
| LLM/ReAct caller → `executeToolCall` | Tool name/arguments and call demand cross into shared MCP execution. |
| MCP server lifecycle/result → cache/audit/caller | Untrusted server behavior affects readiness, logs, and returned result. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-16 | Elevation of Privilege | manager start path | mitigate | Start only repository-tested, policy-valid config; one server-ID entry; factory owns launch/remote validation. |
| T-02-17 | Denial of Service | calls, queues, processes, hangs | mitigate | Enforce 20/32/4/50 caps, resolved idle predicate, hard timeout, cancellation grace, generation-deduped close/error recovery, circuit breaker, bounded jittered recovery. |
| T-02-18 | Tampering | lifecycle/cache state | mitigate | Full discovery transaction before Ready/cache publish; stale cache admin-only; known notifications manager-owned. |

| T-02-20 | Repudiation | MCP operation lifecycle | mitigate | Persist server, transport, method, request ID, duration, status, sanitized error code with bounded retention. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | No package install in this plan. |
</threat_model>
