<interfaces>
New public contract consumed by `processManager.js`:
- `new McpJsonRpcClient(transport, { onNotification, onTransportLifecycle })`
- `client.start()`
- `client.initialize(params, { timeoutMs })`
- `client.listTools({ timeoutMs })`
- `client.callTool(name, arguments_, { timeoutMs })`
- `client.close(reason)`

Every outbound request ID is `crypto.randomUUID()` string. `client` uses raw SDK transports only; it must not import or instantiate SDK high-level `Client`.
`onTransportLifecycle(event)` is manager-owned and receives only `{ type: "error" | "close", code, retryable: true }`; it runs asynchronously after client rejects affected pending work. It must never receive raw `Error`, stderr, URL, environment, arguments, or result data.
</interfaces>
</context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| manager → MCP transport | Server-owned JSON-RPC frames cross into child or remote MCP server. |
| MCP transport → pending map | Untrusted frames may arrive out of order, malformed, duplicated, or after close. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `McpJsonRpcClient` response routing | mitigate | Route only exact UUID request IDs; never broadcast frame contents; close rejects pending work. |
| T-02-02 | Denial of Service | pending requests and timers | mitigate | One settlement helper clears timer/map entry on reply, send error, timeout, and close. |
| T-02-03 | Tampering | outbound JSON-RPC | mitigate | Construct JSON-RPC 2.0 frames internally; validate lifecycle result before next method. |
| T-02-SC | Tampering | npm install | mitigate | Install only Package Legitimacy Audit approved `@modelcontextprotocol/sdk@1.30.0`; no [ASSUMED] or [SUS] package. |
