# Phase 5 Plan 01: MCP Server REST APIs & Process Synchronization

## Goal
Implement `/api/mcp/servers` and `/api/mcp/servers/[id]` (plus `/api/mcp/servers/[id]/restart`) with full CRUD, validation, dashboard session auth protection, and automatic `McpProcessManager` lifecycle management (start/stop/restart/sync).

## User Requirements
- MCP-API-01: `/api/mcp/servers` (GET, POST, PUT/PATCH, DELETE) managing MCP server configs and runtime states.

## Proposed Changes
1. **Create `src/lib/auth/apiAuthGuard.js`:**
   - Helper function `requireDashboardAuth(request)` checking `getSettings().authMode` and `getDashboardAuthSession()`.
   - Returns `{ session, errorResponse }`. If auth enabled and invalid token, returns `401 Unauthorized`.
2. **Create `src/app/api/mcp/servers/route.js`:**
   - `GET`: List servers with query filtering (`?enabled=`), attached runtime status from `getProcessManager()`, and cached tool counts.
   - `POST`: Validate payload (`name`, `transport`, `command`, `args`, `env`, `url`, `enabled`), create record via `createMcpServer`, start process & sync cache if enabled.
3. **Create `src/app/api/mcp/servers/[id]/route.js`:**
   - `GET`: Fetch single server by ID with its status and cached tools.
   - `PUT`/`PATCH`: Update server config or toggle enabled. If config changed or disabled, sync process manager (stop old/start new).
   - `DELETE`: Stop running process session and delete server & tool cache from DB.
4. **Create `src/app/api/mcp/servers/[id]/restart/route.js`:**
   - `POST`: Restart running server process and resync tool cache.
5. **Unit Tests:**
   - `tests/unit/api/mcp-servers.test.js`: Test auth check, validation, CRUD actions, and mocked process manager invocations.
